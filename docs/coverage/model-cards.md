# Screening benchmarks from model cards

Reviewed November 21, 2026 for the v2 admission decisions below. For the current Writing and Design v3 roster, see the [Sophon review](sophon-writing-design.md). A model card establishes that a lab used a benchmark. To use it for model selection, we also need a defined task, a common evaluation protocol, identifiable model configurations, and enough shared configurations to put the results on the domain scale. A lab's comparison table often includes numbers copied from an earlier release. We count the underlying evaluation once.

Google's November 18 Gemini 4 Neon card reports FrontierCode 2.0, Terminal-Bench 4.1, MKA, HLE-Diamond and Terminal-Bench-Science, all represented in ProChoice. It also identifies recent tests of chart reading, mathematical research, software maintenance and professional workflows. OpenAI's GPT-5.4 release and Anthropic's Fable 5 system card provide independent adoption evidence for several benchmark families. Edition, tools and effort still have to match before individual scores can be pooled. [DeepMind model card](https://deepmind.google/models/model-cards/gemini-4-neon/) · [OpenAI release](https://openai.com/index/introducing-gpt-5-4/) · [Anthropic system card](https://www-cdn.anthropic.com/d00db56fa754a1b115b6dd7cb2e3c342ee809620/Claude%20Fable%205%20%26%20Claude%20Mythos%205%20System%20Card.pdf)

The three Surge instruments use a November edition identifier in ProChoice. Their lifecycle ages start with the producer's original public announcements. The source pages are live leaderboards without immutable result URLs. The raw cache retains their published values, source row names and links. An unexplained change of tasks, units, judges or tool permissions calls for an edition review before comparing releases. Webflow's website publication time does not establish when a model ran.

## Reading the weights

The quality diagnostic estimates repeatability and separation among leading providers. The [v3 allocation](measurement-families.md) gives each measurement family equal weight. Empirical quality weighting had mixed results on held-out feeds. It cannot establish the absence of training contamination, independence between tests, or predictive validity for an occupation. To see how much the published order depends on one data feed, open a domain's Methodology panel and expand the feed-removal table. It reports how many affected configurations still have enough evidence, alongside Kendall rank agreement for those that survive. Keeping the calibration fixed isolates the effect of removing observations. A feed can collect results from several different benchmark authors. [Himmi et al., Findings of EMNLP 2024](https://aclanthology.org/2024.findings-emnlp.688/)

The daily audit also compares published rankings with results on shared benchmarks and tests how well other feeds predict each omitted benchmark. [Rank evidence](rank-evidence.md)

## Maintaining the roster

On a new model or benchmark release, compare the issuing lab's table and evaluation notes with the domain reviews. Trace any new row back to the benchmark producer. Record its task unit, evaluator version, tool permissions, model identities, uncertainty and denominator in the review. For an existing task, check whether a new leaderboard is an independent run, a copy, a subset, or the same items with a new judge. Keep one measurement of each task under each protocol. Revisit exclusions when more comparable rows become public.

Each admitted source is mandatory in daily ingestion. Changes to the active roster or benchmark edition require a new domain MAJOR epoch. The validator checks the prior archive, the new calibration, every active partition and a replay from raw data. Daily audits track separation and sustained saturation. A retirement trigger calls for a recorded roster decision and a new epoch. [Ingestion rules](../../.rules/ingestion-and-lifecycle.md) · [Scoring rules](../../.rules/psychometrics-and-pareto.md)
