# Sophon coding and harness review

November 21, 2026. Sophon supplied discovery records. The score checks below use the producers' own releases. The catalog response contained 630 records, of which 36 used the domains `code` or `coding` after case folding. Thirteen of those 36 had a Sophon score. Searching titles and descriptions also found terminal, repository and scientific-programming evaluations filed under other domains. A name with an Inspect, Prime or OpenReward prefix often identifies another implementation of an existing benchmark. [Sophon evaluation catalog](https://sophon.at/evals)

## What contributes to Coding

| Scored instrument | Requested work | Why it represents that work |
| --- | --- | --- |
| FrontierCode-AA 2.0 | Change an existing repository to meet a maintainer's request | 132 private tasks with maintainer-oriented grading. In the November comparison before deduplication, 74 price-eligible configurations had results. DeepSWE had 61, LiveBench Coding 26 and SWE-bench Pro 8. DeepSWE had stronger measured separation, but FrontierCode covered more configurations and calibrated across all nine providers. All four remain inspectable. Only FrontierCode contributes repository changes to the composite. [Producer protocol](https://artificialanalysis.ai/evaluations/frontiercode-2-0) |
| Code Migration v1.1 | Port a specified repository to another language | Scores the migrated repository on the producer's tests under one Pi setup. Replacing the language is part of the task specification. [Vals leaderboard](https://www.vals.ai/benchmarks/code-migration-v1-1) |
| MirrorCode | Reconstruct software behavior from examples | Measures behavioral replication with hidden checks. The producer designates the inputs and the required observable behavior. [Epoch benchmark](https://epoch.ai/benchmarks/mirrorcode) |
| ALE-Bench | Optimize the score of a contest algorithm | Judges the quality of feasible solutions to AtCoder Heuristic Contest problems. The outcome is an optimization objective. [Sakana's official release](https://github.com/SakanaAI/ALE-Bench) |
| ITBench-AA | Identify the contributing entities in a service incident | Agents inspect a snapshot of a Kubernetes incident and submit a diagnosis. The score penalizes false positives. No repository change is required. [Evaluator protocol](https://artificialanalysis.ai/evaluations/itbench-aa) |

Terminal-Bench 4.0 spans software implementation, operations, science and other fields. FrontierSWE v2 combines implementation, performance optimization, scientific computing, visual reasoning and AI research. Both totals include work already represented in Coding. The full scores remain available as standalone results. SciCode-AA was retired in v2. [Terminal-Bench 4.0](https://artificialanalysis.ai/evaluations/terminalbench-4-0) · [FrontierSWE v2](https://www.frontierswe.com/blog/v2) · [Earlier coding audit](coding-research.md)

## Other Sophon candidates

| Candidate | Decision |
| --- | --- |
| LiveCodeBench | Its official generation feed contained 29,540 observations, 28 model labels and 1,055 problems. Problem dates ran from May 8, 2023 through April 7, 2025. Only two literal model labels resolved to a checkpoint in the v2 Coding calibration roster, across two providers, before matching effort. Date-stamped questions would support a prospective window if five providers were measured on a common fresh window. The official board does not currently establish one. [Official results JSON](https://livecodebench.github.io/performances_generation.json) · [Submission repository](https://github.com/LiveCodeBench/submissions) |
| LiveCodeBench Pro | Competitive programming remains a relevant gap. The authors publish the judge and problem sets and ask submitters to send result files by email. Their repository listed no published panel of those result files. The linked leaderboard domain returned HTTP 404 on the review date. A missing leaderboard at that URL does not establish saturation. [Producer toolkit](https://github.com/GavinZhengOI/LiveCodeBench-Pro) · [Dataset](https://huggingface.co/datasets/QAQAQAQAQ/LiveCodeBench-Pro) |
| Aider Polyglot | The owner YAML had 69 runs, 63 covering the full 225 tasks, and four distinct edit formats across all runs. The latest dated run was October 3, 2025. Seven full-panel row labels resolved literally to checkpoints in the v2 Coding roster across only Meta and OpenAI. First-attempt and second-attempt passes belong to the same exercise. This is evidence about an older Aider setup; it also supplies no fixed-model comparison between harnesses. [Aider leaderboard](https://aider.chat/docs/leaderboards/) · [Primary YAML](https://raw.githubusercontent.com/Aider-AI/aider/main/aider/website/_data/polyglot_leaderboard.yml) |
| FeatureBench | A credible alternative repository-change instrument. On the full panel, 4 of 8 rows used OpenHands, across three labs. Its lite panel had 20 rows, 14 on OpenHands, but the score records omit reasoning effort. A separate routed Claude Code configuration cannot be merged with a fixed-model OpenHands run. FeatureBench is outside the index on breadth and attribution grounds, and would need to compete with FrontierCode for the same work family. [Full results](https://libercoders.github.io/FeatureBench/leaderboard/data/full.json) · [Lite results](https://libercoders.github.io/FeatureBench/leaderboard/data/lite.json) |
| FrontierCS | The November FrontierCS 2 board tests restoration of a missing research contribution. Rows use provider-specific harnesses and the publisher documents fallback models on two Claude runs. The FCI also uses 90% intervals and a Kimi reference scale. In v1.1 the seven displayed algorithmic rows use multiple harnesses from three model providers. The earlier v1.0 single-attempt scores use a different scoring rule. Keep these as separate external evidence on CS research. [Current protocol](https://frontier-cs.org/) · [Versioned algorithmic board](https://frontier-cs.org/v1/) |
| KernelBench and ComputeEval | GPU-kernel correctness and speed would add a distinct task. KernelBench's producer requires an architecture, baseline and precision to interpret fast-k performance. It disclaims validation of third-party results. A mixed hardware or mixed precision table cannot establish a common cost or performance scale. Sophon lists no scored ComputeEval panel. [KernelBench protocol](https://github.com/ScalingIntelligence/KernelBench) · [ComputeEval record](https://sophon.at/evals/compute-eval) |
| IDE-Bench and InfraResolutionBench | The IDE-Bench producer page was client-rendered and its linked public repository returned 404 at review. Sophon reports four frontier organizations, short of proving five matched providers with known IDE, checkpoint and effort. The InfraResolutionBench record points to a community Prime environment and its scores, not a separate harmonized release. Incident diagnosis is already represented by ITBench. [IDE-Bench](https://www.ide-bench.com/) · [InfraResolutionBench environment](https://app.primeintellect.ai/dashboard/environments/kariminal/infraresolutionbench) |
| SWE-bench editions, SWE-Gym, SWE-Lancer and Terminal-Bench variants | Verified, Lite, Multilingual and Multimodal are different editions or slices of repository work. A wrapper or translation supplies no extra general repository-change budget. No multilingual panel on the eligible controls passed the protocol checks in this review. The Terminal-Bench owners explicitly describe 4.1 as a regrade of 4.0. A hardness subset is likewise part of its parent task pool. [SWE-bench](https://www.swebench.com/) · [Terminal-Bench revision](https://www.tbench.ai/news/terminal-bench-4-1) · [SWE-Lancer and multilingual screening](coding-research.md) |
| HumanEval, MBPP, APPS, ClassEval, DS-1000, BigCodeBench and their wrappers | These can measure test-based function or class synthesis, but the Sophon records and mirrors do not establish a shared, post-release task window and matched five-provider panel for a current measurement. In particular BigCodeBench-Hard selects problems from BigCodeBench-Full. Future independent, private function-synthesis tasks remain worth measuring. [HumanEval](https://github.com/openai/human-eval) · [BigCodeBench](https://github.com/bigcode-project/bigcodebench) · [DS-1000](https://github.com/xlang-ai/DS-1000) |
| MLE-bench, MLRC-Bench, CORE-Bench and PaperBench | Kaggle competition medals and paper replication measure ML research workflows. Their scores do not measure maintenance of a software repository or isolate a harness effect. For example, MLE-bench compares model and scaffold combinations across 75 competitions. Keep ML engineering results outside the software stacks composite. [MLE-bench](https://openai.com/index/mle-bench/) · [PaperBench source audit](coding-research.md) |

The literal-label counts above are an upper bound on clearly attributable runs before checking effort, not a claim that every other historical label names an unknown model. Sophon's frontier-organization counts are also different from the number of verified shared models. Neither can substitute for matching the publisher's task set, checkpoint, effort and test environment.
